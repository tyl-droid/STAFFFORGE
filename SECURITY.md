
# Security Policy

StaffForge is designed with privacy, transparency, and user control as core priorities.

This document explains how to report security issues and how the project handles security concerns.

---

## Supported Versions

| Version | Supported |
| ------- | --------- |
| 1.0.x   | Yes       |

Older versions may not receive active support.

---

## Reporting a Vulnerability

If you discover a vulnerability, please report it responsibly.

Contact:

[CommunityShieldOfficial@gmail.com](mailto:CommunityShieldOfficial@gmail.com)

Please include:

* A clear description of the issue
* Steps to reproduce
* Affected files or components
* Screenshots or logs if useful
* Potential impact
* Suggested fix if known

---

## Do Not Publicly Disclose First

Please do not publicly disclose serious vulnerabilities before giving us a reasonable chance to investigate and fix them.

This helps protect users.

---

## Security Scope

Relevant security issues include:

* Data leaks
* Authentication issues
* Unauthorized access
* Unsafe file handling
* Insecure integrations
* Hidden telemetry
* Unexpected data uploads
* Malicious modified builds
* Browser extension abuse

---

## Privacy Commitments

StaffForge is local-first by default.

The project should not include:

* Hidden tracking
* Secret data collection
* Automatic application submission
* Unauthorized remote access
* Credential harvesting

---

## Security Best Practices for Users

Users should:

* Download only from official sources
* Scan installers before running
* Keep Windows updated
* Avoid unofficial modified builds
* Use strong account passwords
* Enable 2FA on GitHub, Google, and payment platforms
* Report suspicious versions

---

## Anti-Scam Reporting

If someone is selling fake or unauthorized StaffForge versions, report it to:

[CommunityShieldOfficial@gmail.com](mailto:CommunityShieldOfficial@gmail.com)

If you believe you were scammed, also report it to the relevant cybercrime authority in your country.
