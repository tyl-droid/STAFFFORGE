# Contributing to StaffForge

Thank you for your interest in contributing to StaffForge.

StaffForge is a community-focused project designed to help Minecraft players organize staff applications, prepare for interviews, and manage moderation career development.

Contributions are welcome from developers, designers, testers, writers, translators, and community members.

---

## Ways to Contribute

You can help by:

- Reporting bugs
- Suggesting features
- Improving documentation
- Testing releases
- Translating the app
- Improving UI/UX
- Reviewing code
- Submitting pull requests

---

## Before Contributing

Please make sure you:

1. Read the README.
2. Review the project goals.
3. Check existing issues before opening a new one.
4. Keep contributions respectful and constructive.
5. Avoid submitting malicious, harmful, or deceptive code.

---

## Development Setup

Clone the repository:

```bash
git clone https://github.com/tyl-droid/STAFFFORGE.git
cd STAFFFORGE
````

Install dependencies:

```bash
npm install
cd web
npm install
cd ..
```

Run development mode:

```bash
npm run dev
```

Run the desktop app:

```bash
npm run desktop
```

---

## Pull Request Guidelines

When submitting a pull request:

* Use a clear title.
* Explain what changed.
* Include screenshots for UI changes.
* Mention related issues.
* Keep changes focused.
* Test before submitting.

Example title:

```text
Add application reminder notification system
```

---

## Code Style

Please aim for:

* Clear variable names
* Readable functions
* Minimal unnecessary complexity
* Safe handling of user data
* No hidden telemetry
* No automatic application submissions

---

## Privacy and Safety Requirements

Contributions must respect StaffForge's privacy-first mission.

Do not add:

* Hidden tracking
* Secret uploads
* Data collection without consent
* Automatic form submission
* Malicious or deceptive behavior
* Credential harvesting
* Unclear network requests

Any feature involving data sync, analytics, or third-party services must be clearly documented and opt-in where appropriate.

---

## Documentation Contributions

Documentation improvements are highly encouraged.

Useful documentation includes:

* Setup guides
* Troubleshooting instructions
* FAQ updates
* Screenshots
* Feature explanations
* Security notes

---

## Community Standards

Please be respectful, helpful, and professional.

Abuse, harassment, scams, impersonation, or malicious behavior will not be tolerated.
